# Flags

A zero-dependency progressive web app for learning the flags of the world with spaced repetition. Plain HTML, CSS and JavaScript — no build step, no npm packages.

Live at **<https://niklasjohannes.github.io/flags/>**. On iPhone, open it in Safari and use Share → Add to Home Screen; after the first load it works offline. See [`docs/SPEC.md`](docs/SPEC.md) for the build plan.

## Layout

| Path | Contents |
| --- | --- |
| `index.html` | App entry point |
| `.nojekyll` | Tells GitHub Pages to serve files as-is, without Jekyll processing |
| `manifest.webmanifest` | Web app manifest (install to home screen) |
| `sw.js` | Service worker: offline cache, deploy updates |
| `css/` | Stylesheets |
| `js/` | App modules (SRS engine, quiz engine, views) |
| `data/` | Country metadata (`countries.json`, generated; see [`docs/DATA.md`](docs/DATA.md)) |
| `flags/` | Vendored flag SVGs |
| `fonts/` | Vendored UI font: Pixelify Sans (variable `.woff2`) and its license, `OFL.txt` |
| `icons/` | PWA / home-screen icons and favicons (generated by `scripts/build-icons.js`) |
| `img/` | Pixel-art check and cross marks for answer feedback (hand-drawn SVG) |
| `scripts/` | Dev-only generators (`build-countries.js` and its hand-maintained overrides, `build-icons.js`, `build-sw.js`) and the dev server |
| `vendor/` | Unmodified upstream inputs (flag-icons code list and license) |
| `test/` | `node --test` suites |

## Running locally

Serve the repo root with the bundled dev server (Python standard library only, binds `127.0.0.1`, sends `Cache-Control: no-store`):

```bash
/usr/bin/python3 scripts/dev_server.py 8004
```

then open <http://127.0.0.1:8004/>. Any static server works too. Opening `index.html` as a file does not, because `fetch` of `data/countries.json` needs HTTP.

To check install and offline behaviour exactly as GitHub Pages will serve them, serve under the project-site prefix:

```bash
/usr/bin/python3 scripts/dev_server.py 8004 --base /flags/
```

then open <http://127.0.0.1:8004/flags/>. The manifest's `start_url` and `scope` and the service worker's scope then all resolve to `/flags/`, `/flags` redirects to `/flags/`, and anything outside the prefix is a 404. `127.0.0.1` counts as a secure context, so the service worker registers over plain HTTP.

### Local preview (Claude Code desktop)

`.claude/launch.json` defines `flags-static`, which runs the same command for the in-app browser preview (at `/`; add `--base /flags/` to its `runtimeArgs` to preview under the Pages prefix). The server finds the repo root from its own path and never reads the working directory. That matters because the preview launcher may be unable to read it.

If the launcher reports `can't open file 'scripts/dev_server.py': [Errno 1] Operation not permitted`, it has no permission to read the checkout. This happens for checkouts under `~/Documents` when macOS has not granted the app access to that folder. A committed config can't fix that. Either grant the Claude app access to the folder (System Settings → Privacy & Security → Files and Folders, or Full Disk Access), or keep the checkout outside the protected folders. In the meantime, run the command above from a terminal or shell session and preview <http://127.0.0.1:8004/> in a browser. Keep any scratch files in the gitignored `.tmp/` inside the checkout.

## Offline and updates

`sw.js` precaches the whole app on first load (shell, data, every flag, icons) and serves it cache-first, so the installed app works with no connection. Its cache name is a content hash of every precached file. **After changing any file the app serves, regenerate it:**

```bash
node scripts/build-sw.js
```

The test suite fails if you forget. A new deploy then installs a new worker, which deletes the old cache and takes over. The page reloads to pick up the new code only when it is on the home screen, never during a practice round or a test.

Icons are drawn by a script too. After changing `scripts/build-icons.js`, run it and then `build-sw.js`:

```bash
node scripts/build-icons.js
```

## Backup

Progress lives only in the browser's storage on the device. "Backup" in the home-screen footer exports it as a JSON file (on iPhone, through the share sheet, e.g. "Save to Files") and imports such a file back, after a confirm.

## Running the tests

Tests use Node's built-in test runner — nothing to install:

```bash
node --test
```

CI runs the same command on every push and pull request.
